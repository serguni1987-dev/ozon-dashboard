# Пульт Ozon — Финансовый дашборд

Единый пульт управления магазином **VIVA HOME TEXTILE** (ИП Метельков С.В.) на Ozon. 
Собирает данные из Ozon API, анализирует и выдаёт готовые действия.

## 📂 Структура проекта

- `app/` — старый пайплайн (P&L, база `ozon.db`, ключи `.env`, `credentials.json`).
- `unitka/` — новый пакет (все модули аналитики и прогнозов).
- `ozon.db` — SQLite база (в `app/`).
- `daily_update.ps1` — скрипт ежедневного обновления (10 шагов).

📝 Ручной ввод — только лист «НАСТРОЙКИ»
Всё, что вводит человек, лежит на одном листе; модули читают его через unitka/settings.py.

A1:B17 — ставка и режим УСН, взносы ИП, период юнит-экономики, остаток на счёте на 1 января, деньги на счёте сейчас, кредиторка, уплаченные налоги, параметры ABC/XYZ, целевая маржа, доля общих расходов Ozon.

Блок «ПЛАН ПО МЕСЯЦАМ» — план по месяцам (выручка, прибыль, маржа, заказы) → KPI, ПУЛЬТ.

Блок «СТРАТЕГИЧЕСКИЕ ЦЕЛИ» — цели (маржа, неликвид, ROI, доля активных) → Стратегии, ПУЛЬТ.

Блок «РАСХОДЫ ПО МЕСЯЦАМ» — закупки, налоги, личные, персонал, административные, коммерческие, прочее → ДДС, P&L (строки 37–39, 48).

Блоки ищутся по заголовку, а не по адресу ячейки — их можно двигать. Старые листы «Ручной ввод», «ДДС Ввод», «План» скрыты и работают только как запасной источник.

💰 Минимальная цена
Юнит-сводка (unitka/calc_unit_summary.py, расчёт в unitka/unit_core.py) показывает по каждому товару цену, ниже которой продажа убыточна:

мин. цена = (себестоимость + логистика и услуги на 1 шт) / (1 − комиссия % − эквайринг % − налог %)

Вторая колонка добавляет рекламу и общие расходы Ozon, третья — целевую маржу. Итог листа сходится с P&L до рубля. Товары с ценой ниже минимальной попадают в ПУЛЬТ первой строкой; закупки по ним блокируются.

## 🧩 Установка на другом компьютере

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1          # или двойной щелчок по install.bat
powershell -ExecutionPolicy Bypass -File .\install.ps1 -WithAI  # + локальная ИИ (Ollama)
```

Установщик проверяет Python, ставит библиотеки, спрашивает ключи Ozon и ссылку на таблицу и пишет их в `app\.env`, проверяет `app\credentials.json`, создаёт пустую базу (`py -m unitka.init_db`), задачу «PultOzonDaily» в Планировщике и запускает самопроверку. Повторный запуск безопасен: существующие `.env`, база и ключи не перезаписываются.

Путей и ID таблицы в коде нет — всё задаётся в одном месте, `unitka/config.py`:

| Параметр | Где задаётся | По умолчанию |
|---|---|---|
| Папка проекта | переменная окружения `PULT_HOME` | папка, где лежит `unitka` |
| `OZON_CLIENT_ID`, `OZON_API_KEY` | `app\.env` | — |
| `PULT_SHEET_ID` — ID Google-таблицы | `app\.env` | таблица владельца проекта |
| `PULT_COSTS_CSV` — файл себестоимости | `app\.env` | `costs_all.csv` в папке проекта |
| `PULT_AI_MODEL` — модель Ollama | `app\.env` | `qwen2.5:3b-instruct` |

Образец — `app\.env.example`. Проверка установки: `py -m unitka.doctor` (с `--offline` — без обращений к Ozon и Google).

## 🧠 План действий и сводка

```powershell
py -m unitka.calc_action_plan          # лист «План действий»: правила из unitka/rules.py
py -m unitka.ai_advisor                # «финдиректор»: суммы и топ-3 действия на сегодня
py -m unitka.ai_advisor --mode mentor  # «наставник»: 3–4 предложения, пишет локальная модель
py -m unitka.ai_advisor --write        # записать сводку на лист «Сводка ИИ»
```

Цифры в плане — из `unit_core` (те же, что в «Юнит-сводке»). Статус задачи в колонке G сохраняется между запусками по паре «правило + SKU». Задачи со статусом «выполнено», «отклонено», «не актуально» в сводку не попадают. Пороги правил можно задать на листе «НАСТРОЙКИ» строками «Неликвид: дней без продаж», «Убыточная маржа, %», «Нет в наличии: дней простоя»; без них действуют 60 дней, −5 % и 7 дней.

Все суммы в сводке считает Python; модель только пересказывает готовые цифры в режиме «наставник», и её ответ сверяется с планом.

Python 3.14, SQLite, gspread 6.2.1.

VPN обязателен для Ozon API и Google API.

Все листы используют batch-запись (обход лимита 429).

При ошибке 429 — повтор с задержкой 65 секунд.

⚠️ Частые проблемы
getaddrinfo failed — VPN не работает. Включите VPN.

429 Quota Exceeded — слишком много запросов к Google. Подождите 1-2 минуты.

no such column — изменилась структура БД. Проверьте PRAGMA table_info(таблица).

mergeCells — безвредное предупреждение Google Sheets.
